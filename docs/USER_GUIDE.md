## 1. 系统概述

Nexus AI Command 是一个 **AI 驱动的企业智能管理平台**，覆盖销售、项目、审批、CRM、OA、HR、财务、知识库等企业核心场景。系统以 AI 对话为核心交互方式，所有操作均可通过自然语言与 AI 助手协作完成。

### 技术架构

| 层级 | 技术 |
|------|------|
| 前端 | React + TypeScript + Vite + TailwindCSS |
| 后端 | FastAPI + LangGraph Agent |
| 数据库 | Supabase (PostgreSQL + Realtime + Auth + Storage) |
| AI 引擎 | OpenAI 兼容 API（支持 GPT、Claude、Gemini 等） |

### 数据流

```
用户输入 → 前端 AI 面板 → FastAPI 后端 (/api/chat)
                              ↓
                     加载用户 AI 配置 (ai_settings 表)
                              ↓
                     LangGraph Agent → AI 网关 (用户配置的 Base URL)
                              ↓
                     流式响应 → 前端实时显示
```

## 3. AI 配置指南（重要）

> **这是使用系统前必须完成的关键步骤。** 每位用户都需要在"AI 配置中心"中配置自己的 AI 连接信息。

### 3.1 配置架构说明

系统采用 **"用户级 AI 配置"** 架构：

- 每位用户独立配置自己的 AI API 连接（Base URL + API Key + 模型）
- 配置保存在数据库的 `ai_settings` 表中，按用户 + 组织隔离
- API Key 在服务端加密存储

**配置优先级**（从高到低）:
1. 用户在 AI 配置中心保存的个人设置
2. 服务端环境变量 `AI_BASE_URL` / `OPENAI_API_KEY`
3. 系统默认值

### 3.2 Boss / 管理员配置

Boss 角色（企业管理员）通常负责采购 AI API 服务，需要配置 **AI 转发商或直连 API 的地址和密钥**。

**进入方式**: 左侧导航 → "AI 配置中心"

**配置步骤**:

1. **Base URL（API 地址）**: 填写您的 AI 服务商提供的 API 地址。常见格式：

   | 服务商 | Base URL 示例 |
   |--------|--------------|
   | OpenAI 官方 | `https://api.openai.com/v1/chat/completions` |
   | Azure OpenAI | `https://your-resource.openai.azure.com/openai/deployments/your-model/chat/completions` |
   | API 中转商 (如 apiyi) | `https://api.apiyi.com/v1/chat/completions` |
   | 自建网关 | `https://your-gateway.com/v1/chat/completions` |
   | Claude API | `https://api.anthropic.com/v1/chat/completions` (需兼容层) |

   > 系统会智能补全 URL：如果只填到 `/v1`，会自动追加 `/chat/completions`

2. **API Key**: 填写对应服务商提供的 API 密钥（`sk-xxx` 格式）

3. **模型选择**: 下拉选择或自定义输入：
   - `gpt-4o` — 推荐，性能均衡
   - `gpt-4-turbo` — 高速版
   - `gpt-3.5-turbo` — 经济版
   - `claude-3-opus-20240229` — Claude 最强
   - `claude-3-sonnet-20240229` — Claude 均衡
   - `google/gemini-pro` — Gemini
   - `google/gemini-1.5-pro-latest` — Gemini 1.5
   - `自定义模型...` — 手动输入模型 ID

4. 点击 **"测试连接"** 按钮验证配置是否正确
5. 测试通过后点击 **"保存配置"**

**Boss 的推荐做法**:
- 使用 API 中转服务（如 apiyi、one-api 等），可统一管理多模型的访问和用量
- 在中转平台上为团队创建子 API Key，设置配额上限
- 将中转平台的 Base URL 和子 Key 分发给团队成员

### 3.3 员工 / 团队成员配置

团队成员有两种配置方式：

**方式一：使用公司统一网关（推荐）**

如果公司搭建了统一的 AI 网关（如 `https://ai.gateway.your-company.com/v1/chat/completions`），所有员工填写相同的：
- Base URL：公司网关地址
- API Key：公司分配的密钥（或公共密钥）
- 模型：公司指定的默认模型

**方式二：使用个人 API Key**

员工也可以自行购买 AI 服务，填写自己的 API Key。

### 3.4 内部网关 vs 外部 API

| 对比项 | 内部网关 | 外部 AI 转发商 |
|--------|---------|---------------|
| **适用角色** | 全体员工 | Boss / 技术管理员 |
| **URL 示例** | `https://ai.gateway.company.dev/v1/chat/completions` | `https://api.apiyi.com/v1/chat/completions` |
| **API Key 来源** | 公司统一发放 | 从转发商平台获取 |
| **用量控制** | 网关层统一限流 | 转发商平台设置 |
| **模型选择** | 网关决定转发到哪个模型 | 直接指定模型 ID |
| **成本** | 公司承担 | 按个人/公司账户计费 |

> **结论**：Boss 账户应该配置 **外部 AI 转发商**（或直连 OpenAI/Claude/Gemini 官方）的 Base URL 和 API Key。如果公司搭建了统一的内部网关，则所有员工使用该网关地址 + 公司分配的密钥。

### 3.5 环境变量配置（部署管理员）

对于自行部署系统的技术管理员，可通过环境变量设置全局默认值：

**前端 `.env`**:
```env
VITE_API_BASE_URL=https://your-backend.com   # FastAPI 后端地址
VITE_SUPABASE_URL=https://xxx.supabase.co     # Supabase 项目 URL
VITE_SUPABASE_PUBLISHABLE_KEY=eyJhbG...       # Supabase 公钥
```

**后端 `.env`**:
```env
OPENAI_API_KEY=sk-your-api-key                # 全局默认 AI API Key
AI_BASE_URL=https://api.openai.com/v1         # 全局默认 AI Base URL
AI_DEFAULT_MODEL=gpt-4o                       # 全局默认模型
SUPABASE_URL=https://xxx.supabase.co          # Supabase 项目 URL
SUPABASE_SERVICE_KEY=eyJhbG...                # Supabase Service Key
```

> 用户在 AI 配置中心保存的个人设置会覆盖环境变量的默认值。

## 4. 核心界面

### 4.1 ChatFirst 布局

系统采用 **"AI 对话优先"** 布局：

```
┌──────────┬─────────────────┬──────────────────────┐
│          │                 │                      │
│  侧边栏   │   AI 对话面板    │     页面内容区         │
│  导航     │   (40%)         │     (60%)            │
│          │                 │                      │
│          │  ┌───────────┐  │  ┌────────────────┐  │
│  战绩中心  │  │ AI 消息流   │  │  │  Dashboard    │  │
│  项目管理  │  │            │  │  │  CRM / 审批    │  │
│  销售管理  │  │            │  │  │  等页面内容     │  │
│  审批中心  │  │            │  │  │               │  │
│  ...     │  │            │  │  │               │  │
│          │  ├───────────┤  │  │               │  │
│          │  │ 输入框      │  │  └────────────────┘  │
│          │  └───────────┘  │                      │
└──────────┴─────────────────┴──────────────────────┘
```

- **左侧**: 导航菜单（按角色显示不同条目）
- **中间**: AI 对话面板，随时可与 AI 助手交流
- **右侧**: 当前页面内容（Canvas），可通过右上角按钮关闭/展开

### 4.2 AI 对话面板

AI 对话面板是系统的核心交互入口：

- **对话**: 直接输入自然语言，AI 助手会理解上下文并执行操作
- **Agent 标签**: 切换不同专业的 AI 角色（销售顾问、审批助手等）
- **附件**: 支持上传文件供 AI 分析
- **语音输入**: 支持语音转文字
- **消息操作**: 复制、重新生成、点赞/点踩

### 4.3 全局搜索（Ctrl+K）

按 `Ctrl+K`（Mac: `⌘K`）打开命令面板，可以：
- 搜索并快速跳转到任意页面
- 直接向 AI 提问
- 切换主题 (`⌘T`)
- 快速访问常用功能

## 5. 功能模块详解

### 5.1 战绩中心（员工仪表板）

**路径**: `/dashboard` | **角色**: 所有人

个人销售战绩总览：
- 绩效评分卡（AI 综合评分）
- 销售趋势图（近期业绩走向）
- 赢率分析
- 周排行榜
- 成就徽章
- **销售数据录入**: 点击"录入"按钮记录当日通话、拜访、成交等数据
- **种子数据**: 首次使用可生成演示数据

### 5.2 总控中心（Boss 仪表板）

**路径**: `/boss-dashboard` | **角色**: 仅 Boss

企业全局管控视图：
- 团队绩效图表 + 热力图
- 营收趋势
- **AI 周报**: AI 自动生成的周度经营分析（现金流、风险预警、激励汇总）
- **异常队列**: AI 自动检测的需要关注的事项
- Top 表现者排行
- 待审批事项集成

### 5.3 销售 AI 管理

**路径**: `/sales` | **角色**: Employee, Manager, Boss

AI 驱动的销售管道：
- **看板视图**: 拖拽商机在不同阶段间移动（潜在客户 → 初步接触 → 需求确认 → 方案报价 → 合同签署 → 成交）
- **AI 优先推荐**: 系统自动按 AI 评分排序 Top 商机
- **商机详情**: 查看客户信息、AI 建议、跟进记录
- **AI 实时推演**: 分析高净值成交机会

### 5.4 CRM 客户管理

**路径**: `/crm` | **角色**: Employee, Manager, Boss

全功能客户关系管理：
- **看板视图 / 列表视图** 双模式切换
- 新建/编辑客户
- 客户详情侧边栏（时间线、联系人、统计）
- 搜索 + 筛选（支持按阶段、关键词过滤）
- 数据导出

### 5.5 智能审批

**路径**: `/approval` | **角色**: 所有人

AI 辅助的审批流程：
- **Boss 视图**: AI 自动扫描常规申请，仅推送异常项目，减少审批负担
- **员工视图**: 支持自然语言/语音提交审批申请，AI 自动分类
- 审批类型：费用报销、请假、采购申请、出差等
- 实时推送审批状态变更

### 5.6 项目管理

**路径**: `/projects` | **角色**: Employee, Manager, Boss

项目全生命周期管理：
- 项目列表（含进度条、状态标签）
- **AI 创建项目**: 输入自然语言描述，AI 自动生成项目结构
- 项目详情页：任务分解、成员、进度跟踪
- 4 种状态：规划中 / 进行中 / 已完成 / 暂停
- Boss 可查看全部项目，员工仅查看参与的项目

### 5.7 标书审阅

**路径**: `/tender-analysis` | **角色**: Employee, Manager, Boss

AI 辅助标书分析：
- 上传标书文档
- AI 自动提取关键条款
- 评分和风险分析

### 5.8 竞品库

**路径**: `/battlecards` | **角色**: 所有人

竞品情报卡片库：
- 竞品对比卡片
- 产品优劣势分析
- 应对话术推荐

### 5.9 目标管理

- **目标看板** (`/target-dashboard`): 所有人可查看个人目标完成进度
- **目标管理** (`/targets`): Boss 设定和分配团队销售目标

### 5.10 合同管理

**路径**: `/contracts` | **角色**: Manager, Boss

合同生命周期管理：
- 合同 CRUD（销售合同、采购合同、服务合同、保密协议等）
- 状态流转：草稿 → 审批中 → 已签署 → 执行中 → 已完成/已终止

### 5.11 OA 办公中心

**路径**: `/oa` | **角色**: 所有人

- **请假管理**: 年假/病假/事假/调休，申请与状态跟踪

### 5.12 人事中心

**路径**: `/hr` | **角色**: Manager, Boss

**路径**: `/finance` | **角色**: 所有人

## 7. 移动端使用

系统完整支持手机浏览器和 PWA 使用：

### 布局

- 表单网格在窄屏自动变为单列
- 工作流设计器在手机端显示"请使用桌面端"提示

## 8. PWA 安装

系统支持安装为桌面/手机应用（PWA）：

### 安装方式
1. 使用 Chrome/Edge 浏览器访问系统
2. 地址栏右侧出现"安装"图标，或系统弹出安装提示
3. 点击安装，系统将以独立窗口运行

### PWA 特性
- 独立应用窗口（无浏览器地址栏）
- 支持离线使用（静态资源缓存）
- API 请求采用 NetworkFirst 策略（优先网络，断网用缓存）
- 自动更新

## 9. 常见问题

### Q: AI 对话没有回复 / 提示连接失败？
**A**: 请检查 AI 配置：
1. 进入"AI 配置中心"
2. 确认 Base URL 正确且可访问
3. 确认 API Key 有效且有余额
4. 点击"测试连接"按钮验证
5. 如果使用公司内部网关，确认网络可达（VPN 等）

### Q: Boss 和员工应该填不同的 AI 配置吗？
**A**: 取决于公司的 AI 使用方案：
- **统一网关方案**: 所有人填相同的公司网关 URL + 公司分配的 Key
- **独立配置方案**: Boss 配置转发商的 URL + Master Key，员工各自配置自己的子 Key
- **混合方案**: 公司提供默认网关，员工可选择使用自己的 Key

### Q: 系统支持哪些 AI 模型？
**A**: 任何兼容 OpenAI API 格式（`/v1/chat/completions`）的服务都可以使用，包括：
- OpenAI (GPT-4o, GPT-4-turbo, GPT-3.5-turbo)
- Anthropic Claude (通过兼容层)
- Google Gemini (通过兼容层)
- 本地部署模型 (如 Ollama, vLLM)
- 各种 API 中转服务

### Q: 如何控制团队的 AI 使用成本？
**A**:
- 在后端环境变量中设置限额：`MAX_TOKENS_PER_DAY`、`MAX_COST_PER_DAY_USD`、`MAX_REQUESTS_PER_DAY`
- 使用 API 中转平台，为每个子 Key 设置月度配额
- 在 AI 配置中心选择更经济的模型（如 GPT-3.5-turbo）

### Q: 移动端某些功能显示不全？
**A**: 部分复杂功能（如工作流设计器）仅支持桌面端。手机端会显示提示并引导使用桌面浏览器。

### Q: 数据安全如何保障？
**A**:
- 用户认证基于 Supabase Auth（JWT Token）
- 数据库使用 Row Level Security（RLS）实现行级权限隔离
- API Key 在服务端加密存储
- 生产环境启用 Sentry 错误监控
- 支持审计日志追踪所有关键操作

### Q: 忘记密码怎么办？
**A**: 在登录页点击"忘记密码"，输入注册邮箱，系统会发送密码重置邮件到您的邮箱。
